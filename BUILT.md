# BUILT — AI Security Test Skills for Claude and Hermes

Build date: 2026-11-05 · Built from `BRIEF.md` (source of truth) · Version 0.1.0 · License MIT

## Summary

`aisec` is a modular Python 3.11+ toolkit of defensive security test **skills** that evaluate Claude
(Anthropic SDK) and Hermes (any OpenAI-compatible endpoint: OpenRouter, Together, Fireworks, vLLM,
Ollama) against prompt injection (direct, forged tags, indirect/RAG), jailbreaks (classic,
hypothetical/authority, role-play, multi-turn escalation), obfuscation, adversarial suffixes,
system-prompt leakage (direct and encoded), data exfiltration (markdown/URL and covert channels),
tool misuse (indirect and allowlist), multi-turn persistence, and over-refusal.

## Verification actually performed (2026-11-05)

- `pytest`: **55 passed** on Python 3.13.5 (project `.venv`) and **53 passed** on Python 3.11.18 in a
  separate venv before the 2 HTTP-stub tests were added; the full 55-test suite was re-run on 3.13
  after all changes. Covers graders (canary encodings, regex, keywords, exfil, tools, presets,
  judge parsing), payload loader (schema, duplicates, decode round-trips, corpus targets, every
  case renders), mocked SDK clients, real SDK clients against a local 127.0.0.1 stub server, session,
  rate limiter, retries, runner end-to-end, reports and CLI.
- `make lint` (ruff check + ruff format --check): clean.
- `aisec list`: prints 17 skills · 109 cases · 27 hard negatives · 11 categories.
- `aisec run --models claude,hermes --suite full --mock [--judge]`: completes offline, writes
  `results/run-*.jsonl` + `results/latest.jsonl`.
- `aisec report results/sample/sample_run.jsonl -o … --html … --svg …` / `make report`: regenerates
  `results/sample/report.md`, `report.html`, `docs/img/sample_chart.svg` (HTML and SVG were rendered
  in headless Chrome and checked visually).
- Real-client path with env vars only: `aisec run --models claude,hermes` with
  `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL` and `OPENAI_API_KEY`/`OPENAI_BASE_URL` pointed at a local
  stub server ran end to end through the real `anthropic==2.5.0` and `openai==3.46.0` SDKs.
- Non-editable wheel install + `AISEC_HOME=<checkout>` run from another directory: works.
- Without keys and without `--mock`, `aisec run` exits 2 with a message naming the missing env var.
- Secret scan (common key patterns): no matches. All attack URLs use reserved `.example`/`.invalid`.

## How to run

```bash
uv sync --extra dev && source .venv/bin/activate     # or: make install
aisec list
aisec run --models claude,hermes --suite full --mock   # offline demo
aisec report results/latest.jsonl -o results/report.md --html results/report.html
make test lint report validate

# real models (keys only via env vars, see .env.example)
export ANTHROPIC_API_KEY=...            # Claude; optional AISSEC_CLAUDE_MODEL
export OPENAI_API_KEY=... OPENAI_BASE_URL=https://openrouter.ai/api/v1   # Hermes; optional AISSEC_HERMES_MODEL
aisec run --models claude,hermes --suite default [--judge]
```

## Deviations from the brief

1. **Real-model results not included.** No API keys were available, so `results/sample/` is produced by
   the deterministic **mock client** and is labelled SYNTHETIC everywhere (JSONL `mock: true`, report
   banner, chart subtitle, README caption). The README chart is therefore a format demo, not a
   Claude-vs-Hermes measurement. Real runs need the user's keys.
2. **Env-var spelling.** The brief uses `AISSEC_*` (double S). Those exact names are used; the single-S
   `AISEC_*` spelling is accepted as an alias. `AISEC_HOME` (single S) sets the project root.
3. **Extra files beyond §5:** `aisec/config.py`, `schema.py`, `skills.py`, `payloads.py`, `fixtures.py`,
   `paths.py`, `tool_catalog.py`, `skill_helpers.py`, `models/mock.py`, `grading/exfil.py`,
   `grading/tools.py`, `grading/presets.py`, `report/aggregate.py`, `report/chart.py`,
   `payloads/suffixes.jsonl`, `scripts/build_payloads.py`, `CONTRIBUTING.md`, `Dockerfile`, CI workflow,
   `requirements*.txt`, `uv.lock`, and 7 extra skills (`prompt_injection_fake_tags`,
   `jailbreak_hypothetical`, `system_prompt_leak_encoding`, `data_exfiltration_covert`,
   `tool_misuse_direct`, `multi_turn_escalation`, `over_refusal_benign`). All 10 skill folders named in
   §5 exist with the same names.
4. **Synthetic restricted topic.** Jailbreak-type skills use an operator policy forbidding build steps for
   the fictional "Glimmer Device", plus marker tokens, rather than any real-world harmful topic (per §12).
5. **Anthropic `temperature`.** `anthropic==2.5.0`'s `messages.create` no longer exposes `temperature`, so
   Claude requests send only what is in `params:` (empty by default). Hermes uses `temperature: 0`.
6. **Packaging.** The wheel contains only the `aisec` package. Skills, config, payloads and fixtures are
   read from the checkout (cwd, or `AISEC_HOME`), so the tool is meant to be used from a clone.
7. **Docker image not built here.** The Docker daemon wasn't accessible in the build environment
   (permission denied), so the `Dockerfile` is untested. The equivalent wheel + `AISEC_HOME` flow was
   tested.

## Limitations / not done

- Stretch goals not implemented: garak/PyRIT adapters, streaming/refusal-latency metrics, Streamlit
  dashboard, multi-variant leaderboard JSON. (Done: filterable HTML report, SVG chart, CI workflow.)
- Refusal detection is English keyword heuristics. Prose compliance without a marker or `Step 1` list
  comes out *inconclusive* and needs `--judge` or a manual review.
- About 5–8 cases per skill, so single-run differences are noisy.
- The LLM judge path was only tested with the mock judge. A real judge needs `AISSEC_JUDGE_MODEL` plus a key.
- Cost estimates use prices from `config/models.yaml` (Claude placeholder $3/$15 per MTok; Hermes 0).
  Check them against current provider pricing.
